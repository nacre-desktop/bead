On the first key, `worker` was 5.097/23.026ms H and 5.136/22.858ms N; `compose` CPU was 3.808/3.622ms and `paint_rounded` 2.760/2.580ms. Steady `paint_rounded` CPU was about 0.17ms.
`menu_query` steady wall/thread-CPU p50 was H 2.458/0.113ms and N 2.586/0.136ms; first-key wall was 17.983/17.683ms with CPU 0.128/0.133ms. Daemon/worker CPU remained separate, about 1.35/0.66ms H and 1.39/0.67ms N at p50.

Desktop relative memory gate, stage-minus-clock UI idle-screen medians (PSS/anonymous MiB): H −0.066/+0.023; N +0.036/0.000. Post-key medians were H −0.016/+0.051 and N +0.087/+0.043; all remain within +0.5MiB PSS/+1MiB anonymous. DRM was not measured and is excluded.
Every accepted arm had 61 idle samples, UI/daemon/worker SwapPss 0, host swap-in 0, complete watchdog/scope cleanup, and OOM delta 0. `MemoryMax=12GiB`, `MemorySwapMax=0`; maximum cgroup peak was 342.6MiB H/264.6MiB N; minimum `MemAvailable` was 11.696/11.846GiB.

Clock provenance: input receipt and `UI_PRESENTED` use `CLOCK_MONOTONIC`; UI CPU uses whole-process `CLOCK_PROCESS_CPUTIME_ID`; stage spans use monotonic wall and `CLOCK_THREAD_CPUTIME_ID`; helper CPU uses process clocks. Sites: `bead-wayland/src/protocols.rs`, `transactions.rs`, `bead-core/src/profile.rs`, `spikes/process-clock.py`.
Rank: (a) worker staging/markup/composition is the largest measured UI CPU path; (c) query wall includes substantial wait with little UI-thread CPU; (d) maxima near 28–30ms coexist with p99 below 11ms and refresh predictions are 0/unknown; (b) decode/allocation is not separately timed. No physical claim follows.
The first typed key exceeds 8ms UI CPU and 16.7ms presented latency, while steady and all-key p99 meet those thresholds in these nested runs. Two pre-fix H diagnostics were excluded; a later H diagnostic was post-hoc validated after correcting the unrelated-frame count gate.
Trace limits: exact per-key successful RPC→result→commit→presentation linkage is proven, but item IDs/query identity are absent; send/return markers lack clocks, so exact RTT is unknown. Burst/stale-query behavior is not proven. Ten pairs are valid, but the changed-item-ID acceptance criterion remains incomplete.
