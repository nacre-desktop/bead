# B0002 full batch — 2026-10-21

## Watchdog teardown fix

Root cause: `run_guarded` observed `systemd-run --scope` exit before its final `memory.events` read. With `--collect`, the transient cgroup may already be removed; concurrently the watchdog can see the missing counters and abort. This can leave phase files even though the runner rejects the arm.

Fix: a small in-scope runner now keeps the measured scope alive after the capture command returns. It publishes the command result and waits for a release marker. The supervisor rechecks runner identity/containment and reads final memory/OOM counters while the scope is still active, stops the watchdog, then releases the runner. Missing counters while held, any OOM increase, watchdog abort, nonzero capture result, or runner/report return-code disagreement still invalidates the arm.

Regression coverage simulates the old post-teardown `memory.events=unavailable` failure, asserts the fixed final read precedes scope release, and verifies missing counters while the scope remains held still invalidate. Full mock suite: `nice -n 10 python3 -m unittest spikes.tests.test_dashboard_capture_windows` —51 passed. `python3 -m py_compile spikes/capture_safety.py spikes/tests/test_dashboard_capture_windows.py` passed.
