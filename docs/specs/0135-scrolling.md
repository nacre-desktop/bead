# Scrolling contract

The shared Wayland scroll policy distinguishes content scroll regions from action gestures. Within content regions, finger-source deltas use absolute logical-pixel movement one-to-one. Finger release (`axis_stop`) can start a decelerating fling. Wheel input uses 100 logical pixels per notch and a 125 ms retargeted ease-out; legacy wheel-axis fallback is converted using 15 logical pixels per notch. Reversing direction discards undelivered forward travel. `value120` units take precedence over discrete and absolute wheel fallbacks. New input cancels an active fling. Wheel updates retarget from the current pose; same-direction updates retain undelivered travel, while a reversal discards it. Finger and other immediate input remove pending wheel motion before delivery. Discrete action gestures remain one event per physical input.

Views expose scroll regions and receive logical deltas. Offset-only changes should reuse layout. Nested regions consume motion while they can move in that direction and may pass exhausted motion to an eligible ancestor. Virtual lists bound materialized rows independently of total list length and use stable item keys to preserve row identity. Hosts provide list data and action policy; the framework owns input conversion, clipping, hit testing, and scroll mechanics.

## Default viewport affordance

Every overflowing Luau `Scroll` owns an overlay scrollbar without reserving content width. `scrollbar=false` opts out, including through the kit virtual list. The thumb represents viewport / total content extent, has a minimum length, and maps dragging to the full bounded offset. Track clicks page with overlap; pointer capture keeps a thumb drag active outside the viewport until release. Scroll input reveals the bar, it fades over 160 ms, and it hides after 1000 ms idle plus the fade. Edge hover and an active drag hold it visible.

The optional `tokens.scrollbar` group overrides neutral defaults: `width=6`, `hover_width=10`, `hit_width=24`, `inset=3`, `radius=3`, `minimum_thumb=24`, `line_step=24`, `page_overlap=24`, `auto_hide_ms=1000`, `fade_ms=160`, `alpha=0.7`, `hover_alpha=1`, `color="onSurfaceVariant"`, `hover_color="onSurface"`. Colors name palette roles (optionally `{role,alpha}`); missing tokens preserve existing hosts. No application supplies scrollbar children. AccessKit ScrollView nodes expose bounded `scroll_y`, `scroll_y_min`, and `scroll_y_max`.

PgUp/PgDn move by a viewport minus a themed 24 logical pixel overlap; Up/Down step one themed line (24 pixels by default); Home/End target the ends. These use the same 125 ms cubic ease, retargeted from the current offset. A focused descendant selects its actual ancestor viewport; otherwise the viewport under the pointer is used. A focused TextInput retains cursor Home/End and arrow handling. Reduced motion removes the ease. Wheel, fling, keyboard and decoration animation use surface frame callbacks; a one-shot timer wakes an idle surface for a distant hide deadline.

Fixed-pitch virtual lists and grids use the framework's `window_index(binding,pitch,prefix,max_offset)` dependency: the first materialized row includes one overscan row, and only a change of that row invalidates Luau evaluation. Variable-height lists retain exact offset invalidation. Spacers or extent boxes carry the full extent without materializing all rows.

## B0240 measurements

Baseline source: `841603f9`; synthetic tests use 300 mixed text rows and a 1000-item kit virtual list at 640×480. The unchanged base was executed before transferring the candidate. CPU renderer, Ubuntu container, unoptimized test build; nominal 60/120 Hz samples evaluate a 100 px / 125 ms ease, with no real output presentation. Timings are elapsed wall time on the CPU path, not a laptop refresh-rate claim; allocation counts are calling-thread Rust global-allocator calls. Raster uses a full viewport damage request; reported dirty area is separately computed by FrameDamage.

At 60 Hz (8 samples), stage medians were 0.867 → 0.363 ms for ordinary rows and 1.193 → 0.172 ms for the virtual list. Allocation medians were 9072 → 5023 and 1659 → 434.5 respectively. The candidate removes repeated ownership-map construction and virtual-list evaluation within the same row window. Separate instrumented runs measured nonzero virtual-list Luau evaluation medians of 0.717 → 0.735 ms and window-boundary layout medians of 0.255 → 0.237 ms; the gain is avoiding those stages between boundaries, rather than accelerating Luau itself. It does not eliminate owned Scene/Node/store copies: the remaining staging allocations are measured above, and renderer resource-key preparation adds roughly 3693 / 268 allocations per frame. **The whole path is not allocation-free, and this debug full-viewport benchmark does not prove 120 Hz.**

Diagnosis before candidate execution: ordinary scrolling already reused Taffy layout, but rebuilt string ownership/ancestor maps and cloned primitives during patching. Virtual-list exact-offset reads evaluated Luau on every sample (23 evaluations across the two rates, versus zero for ordinary rows; 25 including both initial builds), even when the row window stayed unchanged. Baseline wheel/fling scheduling used refresh-estimated timers; integer 8,333,333 ns timer steps needed 16 callbacks to reach 125 ms, whereas rational 120 Hz frame timestamps need 15 (60 Hz needs 8). Debug full-surface raster already exceeds the 8.33 ms budget and must not be presented as a 120 Hz proof.

The 100 px notch and finger 1:1 conversion are retained. For comparison, [Qt 6.10 platform defaults](https://raw.githubusercontent.com/qt/qtbase/6.10/src/gui/kernel/qplatformtheme.cpp) specify 3 wheel lines and a 20 px scroll step; [Qt's slider wheel policy](https://raw.githubusercontent.com/qt/qtbase/6.10/src/widgets/widgets/qabstractslider.cpp) multiplies those (60 px/notch before host overrides). Bead's 100 px is already 1.67× that generic default, so increasing travel is not supported by this evidence. These are source-policy comparisons, not measurements of installed toolkit applications.

For pixel input, six +24 px finger samples deliver 144 px before release in Bead. [Qt Quick's pixel-delta path](https://raw.githubusercontent.com/qt/qtdeclarative/6.10/src/quick/items/qquickflickable.cpp) likewise accumulates the supplied pixel deltas for dragging (144 px input for that sequence, before thresholds, bounds, and release physics). Bead retains its existing 2645.664 px/s² endpoint calculation: an ideal 1500 px/s release targets approximately 425.2 additional pixels unless bounded. Its separate duration policy is 1500/2300 seconds (652 ms), with cubic deceleration to rest. The gesture comparison distinguishes direct pixel travel from the release fling; it does not assert that toolkit velocity filtering or endpoints are identical.

The real headless input trace also exposed an ingress defect outside the Session-only benchmark: the default folder host did not forward `Session::scroll_regions` to `SceneSource`. Before that hook was fixed, one discrete wheel notch delivered **15 px in one immediate event**, and six +24 px finger samples delivered **144 px with no fling** after `axis_stop`. Content was incorrectly classified as an action gesture. Forwarding the viewport contract restores the existing 100 px notch/ease and release physics without tuning their constants. This trace was taken before applying the host hook; operational captures and raw event logs remain untracked.


The optimized candidate repeats the same CPU benchmark with stage / prepare / diff / raster medians of **40 / 193 / 33 / 245 µs** for 300 rows and **6 / 12 / 3 / 167 µs** for the virtual list at nominal 120 Hz. This identifies debug raster overhead rather than a release CPU throughput limit in this synthetic case. These are CPU/pixman headless supporting measurements, not measured presentation on a 120 Hz laptop.

After fixing ingress, the private headless trace delivers one notch as nine eased events totaling **100 px over 132.3 ms**, followed by six direct finger samples totaling **144 px** and approximately **428 px** of release fling. The headless compositor actually grants callbacks about every 16.5 ms despite an advertised 120 Hz mode. Callback timestamp unit tests cover 8 / 15 steps at 60 / 120 Hz. The private folder app has zero `UI_ERROR` entries. Inspected active/idle captures show identical content and a difference only in the right gutter (x=791..796): a proportional thumb after scrolling and background after idle. Raw screenshots and logs remain untracked.

Validation includes controlled-clock geometry, fade/hover/capture/track/opt-out tests; keyboard paging/endpoints and TextInput cursor ownership; actual cached Luau evaluation counters; virtual extents with both all 1000 rows and only a loaded prefix; and whole workspace/feature/private-service/license/minimal-host checks. No image golden changed. The cached-vs-full-layout nested-scroll comparison opts out of the time-dependent overlay to compare content geometry, including fractional offsets.

Known limits: the current Luau `Scroll` contract is vertical only, so no horizontal content region exists to decorate. Variable-height virtual lists retain exact-offset Luau evaluation. Owned scene/node/store copies and renderer resource-key creation remain measured allocations; allocation-free whole-frame scrolling is not achieved by this unit. The owner’s live refresh/memory acceptance and product-shell visual parity remain coordinator checks; a standalone framework proof does not substitute for them.

Memory budget for the synthetic scenarios: 64 KiB of additional retained metadata. Cached topology uses three `Option<usize>` indices per scene layer plus one `usize` owner per primitive and per interaction node (about 16.5 KiB for 300 simple rows, plus vector headers). This replaces transient string-map construction; it intentionally spends bounded retained memory for smoother input. Scrollbar activity exists only after interaction and is discarded after fade-out; idle regions need no activity-map entry. Two owner/enabled flags are stored in existing nodes, and theme/config/callback state is per session/surface, not per row. These are explicit storage-accounting estimates, not RSS or laptop memory-gate measurements.
