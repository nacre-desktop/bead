# 0247 — Network devices service

`bead_services::network` is an independent event-driven client of NetworkManager on the system bus, separate from the Desktop `Network` summary, `Config` and `Snapshot`. `Network::start(connection)` returns a handle with `snapshot()`, `subscribe(callback)` and `action(..) -> Result`. It walks `org.freedesktop.NetworkManager` (`Devices`, `ActiveConnections`, `PrimaryConnection`, `WirelessEnabled`, `WirelessHardwareEnabled`), each `Device` (plus `Device.Wireless` for Wi-Fi), each `AccessPoint`, each `Connection.Active`, and `Settings.Connections` with `Settings.Connection.GetSettings`, keeping only a saved profile's id, type and SSID (`GetSettings` never returns secrets; nothing is logged). After that it follows `PropertiesChanged`, `DeviceAdded/Removed`, `AccessPointAdded/Removed`, `NewConnection`, `ConnectionRemoved`, `Updated`, `Removed` and `NameOwnerChanged`, merging changed properties into its cache and fetching only objects it has not seen; there is no polling. When NetworkManager leaves the bus the snapshot becomes unavailable and empty.

`NetworkSnapshot` holds `available`, `wireless_enabled`, `wireless_hardware_enabled`, `primary` (`kind` wifi/ethernet/vpn/other, `name`, `device` interface, `state`), `devices` (`path`, `interface`, `kind`, `state`, `active_connection`), `access_points` and `known_connections` (`path`, `id`, `kind`, raw `ssid`). Access points are deduplicated by raw SSID across Wi-Fi devices, strongest first, with `active` set if any access point of that SSID is active; hidden (empty) SSIDs are skipped. Each carries the display SSID (lossy UTF-8), the raw bytes used for matching and activation, `strength`, `security` (`open` means no credentials are needed, including OWE; otherwise `wpa`, `wpa3`, `enterprise` or `wep`), `frequency_mhz`, `known` (a saved Wi-Fi profile has the same raw SSID) and the device that sees it.

Actions are validated against the current snapshot: `SetWirelessEnabled(bool)` sets `WirelessEnabled`; `Scan(device)` calls `RequestScan` on a Wi-Fi device, at most once per device every 10 seconds; `ActivateKnown(connection, device)` calls `ActivateConnection`; `ActivateOpen(ssid, device)` calls `AddAndActivateConnection` with only the type and SSID, and only for an `open` network, so NetworkManager completes the profile; any other security returns `secured network needs a password agent`; `Disconnect(device)` calls `DeactivateConnection` on the device's active connection; `Forget(connection)` calls `Settings.Connection.Delete`. `start_system` keeps the runtime that built its bus connection alive in the worker, so the connection keeps receiving after it returns.

Folder apps opt in with `[services].desktop = [..., "network_devices"]` (`network` still means the Desktop summary). The shared `FolderServicesRuntime` starts the service only when declared and publishes `desktop.network_devices.available`, `wireless_enabled`, `primary_name`, `primary_kind`, `access_points` (list of `{ssid, strength, security, active, known}`) and `known` (list of `{id, kind}`). Host actions: `wireless` (Bool), `scan` and `disconnect` (no argument; the first Wi-Fi device, or the first connected one), `connect` (Text SSID: a known network activates its saved profile on the device that sees it, an open one is added and activated, a secured unknown one reports the agent error) and `forget` (Text profile id; ambiguous ids are refused).

Out of scope: a secret agent or any password entry, VPN management, enterprise authentication, mobile broadband, hotspot creation, and connection editing. No temporary duplicate implementation was introduced. Memory: nothing runs unless declared; a declared service adds one worker thread and a property cache proportional to visible devices and access points (budget ≤ 1 MiB, not measured in this unit). No UI parity capture applies: this adds no rendered surface.

Evidence: the public NetworkManager D-Bus reference for [NetworkManager](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.html), [Device](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.Device.html), [Device.Wireless](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.Device.Wireless.html), [AccessPoint](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.AccessPoint.html), [Connection.Active](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.Connection.Active.html), [Settings](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.Settings.html), [Settings.Connection](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.Settings.Connection.html) and the [D-Bus enum types](https://networkmanager.dev/docs/api/latest/nm-dbus-types.html); no application source was consulted. `tests/network_private_bus.rs` runs a fake NetworkManager on a private bus through `start_system` and covers discovery, deduplication and security classes, strength and active-AP changes, access point and device add/remove (including discovery from `AccessPointAdded` alone), every action reaching the fake (with no security section for open networks), invalid inputs, the agent error, the scan limit with an explicit clock, owner loss and return, and prompt shutdown on a closed connection. Host tests cover the store projection, action routing and SSID/profile resolution.
