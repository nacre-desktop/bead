# Plugins v1 framework contract

A plugin directory named for its ID contains `plugin.toml` and Luau files. The manifest has a plugin ID, name, version, API level, optional descriptive fields and capabilities, one or more `[[widget]]` entries, and optional plugin settings. Unknown manifest fields are rejected. IDs are 1–64 lowercase ASCII letters/digits/hyphens, beginning with a letter. Widget IDs are unique and equal the plugin ID or begin with `<plugin-id>.`; entry paths must be relative `.luau` paths. A host discovers at most 64 plugins; each plugin may contain at most 64 Luau files, each at most 256 KiB. Supported setting types are `toggle`, `choice`, `number`, `slider`, and `text`; values are checked against their manifest schema.

The host supports a cumulative API range `API_MIN..=API_LEVEL` (currently both 1). A widget entry returns a factory `function(api) -> package`. `api.ui` and `api.kit` expose Bead UI and kit modules; `api.plugin` provides the plugin ID and plugin-level settings; any `api.app` helpers are host-defined and outside the versioned framework API. A plugin may require `bead.ui`, `bead.kit`, and its own files only.

Capabilities are prefix grants: `topic:<prefix>` permits matching store reads and `action:<prefix>` permits matching emitted actions. The framework checks reads at resolution and checks every store binding and action in the rendered plugin subtree. Framework interaction state (`bead.focused`, `bead.hovered`, `bead.focus_visible`, `bead.pressed`, `bead.viewport.*`, `bead.preview.*`) is readable without a declared capability. `network`, `files`, and `exec` may be listed but have no API 1 host function and are denied by omission. Luau sandboxing is a stability boundary, not a security boundary; hosts should enable only trusted plugins.

The host supplies discovery roots, state path, and management policy. Bundled plugins are enabled by default unless disabled; user plugins are disabled by default. A bundle opts in with `"plugins": true` in its `bundle.json`. Invalid manifests or unreadable sources are reported and not mounted. A load or render fault is reported, persists until re-enabled, and isolates that plugin; disabling or faulting removes it on a later mount. State and directory changes can be watched so the host can reload affected views. Product routes, update policy, and application helpers remain host-owned.
